# 长跑 Agent 重启策略

## 原则

重启是一种受控恢复策略，不是破坏已有工作的许可。

当前没有活跃批次。恢复会话不得把 `.agent-loop/archive/` 中的已完成批次当作仍需继续执行的队列。

## 重启触发条件

满足任一条件时，可以考虑提出重启方案：

- 连续 3 个工作切片都失败在同一条验收标准上。
- 当前实现已经偏离 `.agent-loop/contract.md`。
- 当前设计需要大范围打补丁，而较小的重写就能满足契约。
- 两次尝试修复后，验证输出仍显示同一个根因失败。
- 代码库形态已经不再匹配 `.agent-loop/progress.md` 中的计划。

## 必需的重启提案

重启前，必须在 `.agent-loop/progress.md` 写入提案，并追加一条日志，说明：

- 为什么考虑重启。
- 会保留什么。
- 会丢弃或重写什么。
- 最小安全回滚或重建目标是什么。
- 哪个验证能证明重启成功。
- 是否需要用户明确批准。

## 无需额外批准即可执行

- 重新规划下一个切片。
- 创建新的草稿文件。
- 在工作区内创建小范围、有明确目标的备份副本。
- 在用户已经要求生成对应输出的前提下，重写仅由当前 agent 运行创建的文件。

## 必须获得用户明确批准

- 删除用户创建的文件。
- 运行破坏性 Git 命令。
- reset、clean 或强制 checkout 某个 worktree。
- 用新架构替换仍可工作的实现。
- 删除不是当前运行创建的大目录或生成产物。
- 创建会复制工作区重要部分的大型备份副本。

## 优先隔离方式

如果项目是 Git 仓库，风险较高的重启优先使用分支或 worktree。如果项目不是 Git 仓库，大型重写前优先使用带时间戳的小范围备份副本。
