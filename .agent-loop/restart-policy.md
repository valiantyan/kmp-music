# 本批次重启策略

## 原则

不要进行破坏式重启。调度跑偏时，先保留本批次已读取上下文和门禁规则，再写明重启提案。

## 重启提案必须说明

- 为什么继续当前状态不如重启清晰。
- 哪些证据支持重启。
- 保留哪些文件、issue 状态和门禁判断。
- 重写哪些调度记录。
- 用哪个 issue 文件和验收门禁证明重启成功。

## 禁止事项

- 不删除用户文件。
- 不运行破坏性 Git 命令。
- 不在协调器线程直接实现业务代码。
- 不在说明/配置会话启动 13 到 17 的 Harness。
- 不跳过未完成 issue 调度后续 issue。
- 不并发派发存在顺序依赖的 issue。
- 不在门禁未通过时把批次标记为完成。
