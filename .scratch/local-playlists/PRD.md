# 本地自建歌单与添加到歌单流程规格

Status: ready-for-agent
Labels: ready-for-agent

## 问题陈述

当前应用已经具备本地歌曲浏览、播放、收藏、专辑和歌手维度浏览能力，但用户还不能把喜欢的本地歌曲按自己的意图组织成本地自建歌单。我的页中已有“歌单”统计位，但它仍是静态占位，用户点击后无法进入真实歌单能力；歌曲更多面板也缺少“添加到歌单”的保存闭环。

用户需要一个只面向当前应用本地数据库的歌单能力：从歌曲更多面板选择已有歌单或创建新歌单，把当前歌曲保存进去；再从我的页进入歌单列表和歌单详情，确认歌曲已经加入，并按歌单顺序播放。这个能力需要同时覆盖手机端和桌面端，并保持界面、状态和持久化结果一致。

## 解决方案

新增“本地自建歌单”能力。用户从非歌单详情页的歌曲更多面板点击“添加到歌单”，打开添加到歌单弹窗；弹窗展示搜索框、新建歌单入口和已存在歌单列表。用户可以选择一个已有歌单后点击“完成”，也可以进入新建歌单弹窗创建歌单。创建新歌单成功后，当前歌曲会直接加入新歌单，并关闭两个弹窗。

我的页头像下方的“歌单”统计项升级为真实数据和真实入口。歌单数量大于 0 时，点击进入歌单列表二级页面；歌单数量为 0 时不跳转，只提示“暂无歌单”。歌单列表页面以首页专辑卡片的视觉形态展示所有本地自建歌单；点击歌单卡片进入歌单详情页。歌单详情页以专辑详情页的视觉形态展示歌单封面、名称、当前可用歌曲数量和歌单歌曲列表，并支持播放全部和点击歌曲播放。

歌单只保存当前应用内已经能拿到的歌曲标识，不新增系统媒体库播放列表导入、外部文件选择、云同步、公开歌单、删除、重命名或移除歌曲等能力。

## 用户故事

1. 作为本地音乐用户，我想把某一首歌曲添加到自己创建的歌单中，以便按自己的听歌场景整理歌曲。
2. 作为本地音乐用户，我想从歌曲更多面板看到“添加到歌单”，以便不离开当前歌曲列表就能保存歌曲。
3. 作为本地音乐用户，我想在添加到歌单弹窗里看到所有已有歌单，以便快速选择目标歌单。

51. 作为手机端用户，我想歌单二级页面仍保留全局迷你播放器，以便浏览歌单时可以继续控制播放。
52. 作为桌面端用户，我想桌面端我的页也能通过“歌单”统计项进入歌单能力，以便跨端体验一致。
53. 作为桌面端用户，我想桌面端也能使用添加到歌单和新建歌单弹窗，以便桌面歌曲列表也能保存歌曲到歌单。
54. 作为桌面端用户，我想桌面端弹窗和手机端共用视觉和逻辑，只做窗口尺寸适配，以便两端行为一致。
55. 作为本地音乐用户，我想添加歌曲后所有相关界面即时刷新，以便不用退出重进就能看到新数量、新封面、新排序和详情页新歌曲。
56. 作为实现者，我想歌单能力只保存当前应用内歌曲标识，以便避免引入外部导入、系统播放列表和云同步边界。

## 实现决策

- 本次新增的领域对象是“本地自建歌单”，它只属于当前应用本地数据库，不承接登录、云同步、系统媒体库播放列表、公开歌单或推荐歌单。
- 数据层新增歌单元信息表和歌单歌曲关系表。歌单元信息至少需要保存歌单标识、名称、创建时间和更新时间；歌单歌曲关系至少需要保存歌单标识、歌曲标识、加入时间和稳定顺序。
- 歌单歌曲关系需要保证同一首歌在同一个歌单中只存在一条记录。重复添加时不新增、不改变原有加入顺序、不更新歌单更新时间、不改变歌单列表排序，但仍返回成功结果。
- 数据库升级必须通过正常迁移完成，不使用破坏性迁移；新增迁移需要保留既有播放、收藏、搜索历史、本地曲库和偏好数据。
- 歌单名称创建前先执行首尾空格裁剪；裁剪后为空时不能创建。
- 歌单名称判重只使用裁剪后的完全字符一致判断，不做大小写归一，不合并中间空格，也不做模糊匹配。
- 默认歌单名从“默认歌单 1”开始，按正整数递增寻找第一个未被完全字符一致占用的名称。
- 搜索歌单只搜索歌单名称，搜索前后空格忽略，大小写不敏感；搜索规则不改变名称判重规则。
- 添加到歌单弹窗打开时不默认选中任何已有歌单。
- 添加到歌单弹窗一次只允许选择一个已有歌单；选中后“完成”才可点击。
- 添加到歌单弹窗搜索框为空时展示全部已有歌单；数据库无歌单时列表区显示“暂无歌单”；搜索无匹配时显示“未找到相关歌单”。
- 添加到歌单弹窗始终保留“新建歌单”入口。
- 从歌曲更多面板进入添加到歌单流程时，应关闭或覆盖来源歌曲更多面板；保存成功后必须关闭本次流程产生的所有临时面板，回到原歌曲列表。
- 用户选择已有歌单并点击“完成”后，当前歌曲保存到目标歌单；保存成功后关闭添加到歌单弹窗，并显示“添加到 xxxx 歌单成功”。
- 用户从添加到歌单弹窗进入新建歌单弹窗并创建成功后，创建歌单、加入当前歌曲、关闭新建歌单弹窗、关闭添加到歌单弹窗，并显示“添加到 xxxx 歌单成功”。
- 新建歌单并加入当前歌曲必须作为一个仓库级原子操作处理；如果加入歌曲失败，不应留下只被创建但没有当前歌曲的空歌单，也不显示成功提示。
- 成功提示中的歌单名称使用最终保存到的歌单名，保留大小写和中间空格，只去掉首尾空格。
- 新建歌单名称为空时提示“歌单名称不能为空”；名称已存在时提示“歌单名称已存在”；校验失败时不关闭弹窗。
- 我的页“歌单”统计值改为真实本地自建歌单数量。数量为 0 时点击不跳转，只提示“暂无歌单”；数量大于 0 时点击进入歌单列表二级页面。
- 手机端歌单列表页是普通二级页面，隐藏底部标签栏，保留全局迷你播放器。迷你播放器由全局界面框架承载，不在歌单页面重复实现。
- 桌面端我的页的“歌单”统计项也升级为真实数量和真实入口。桌面端进入歌单列表和歌单详情时使用桌面端既有二级内容区域语义。
- 歌单列表页使用与首页专辑卡片一致的视觉节奏展示歌单。卡片展示歌单名称、当前可用歌曲数量和封面。
- 歌单列表排序为更新时间倒序；时间相同时按歌单名称升序兜底。创建歌单和真正新增歌曲关系时会更新目标歌单更新时间；重复添加命中既有关系时不更新目标歌单更新时间。
- 当前可用歌曲统一以当前应用歌曲仓库能解析出的可播放歌曲集合为准；歌单中保存但当前无法解析为可播放歌曲的关系继续保留在数据库中，但不进入封面、数量、详情列表或播放队列口径。
- 歌单封面取歌单内第一首当前可用歌曲的封面；空歌单或无可用歌曲时使用默认封面。
- 歌单详情页使用与专辑详情页一致的二级页面视觉形态，展示歌单封面、名称、当前可用歌曲数量、播放全部按钮和歌单歌曲列表。
- 歌单详情页的歌曲列表只展示当前仍可用歌曲。不可用歌曲的关系记录保留在数据库中，不在本次界面中计数或展示。
- 歌单列表卡片歌曲数量、歌单详情顶部歌曲数量和歌单详情列表数量都使用当前可用歌曲数量。
- 歌单详情页中歌曲按稳定顺序升序展示；稳定顺序由首次加入歌单时写入，加入时间可作为展示和审计字段。播放全部也按同一稳定顺序建立歌单播放队列。
- 歌单详情页点击任意歌曲时，用整个歌单当前可用歌曲列表建立歌单播放队列，并从被点击歌曲开始播放。
- 存在歌单但当前可用歌曲数量为 0 时，歌单卡片仍可点击进入详情页；详情页显示“暂无可播放歌曲”。
- 空歌单详情页仍显示“播放全部”按钮，但按钮置灰不可点击。
- 歌单详情页中的歌曲更多面板保留原有歌曲操作，但移除“添加到歌单”入口。
- 非歌单详情页的歌曲更多面板新增“添加到歌单”。该入口应挂在全局歌曲更多面板能力上，而不是在每个列表中复制实现。
- 添加成功后需要即时刷新所有相关界面状态，包括我的页歌单数量、歌单列表排序、目标歌单封面、目标歌单当前可用歌曲数量和目标歌单详情歌曲列表。
- 手机端和桌面端共用同一套添加到歌单弹窗、新建歌单弹窗、数据逻辑和状态规则。桌面端弹窗居中展示，并按窗口尺寸做约束；小窗口下遵守最大高度限制和内部滚动。
- 添加到歌单弹窗的最大高度受屏幕或窗口高度三分之二约束，超过时内部列表滚动。
- 添加到歌单弹窗和新建歌单弹窗需要按用户提供的设计稿节点做视觉还原。添加到歌单弹窗对应节点为 974:690，基准尺寸为 440px 宽、679px 高的白色圆角容器；新建歌单弹窗对应节点为 974:672，基准视觉为 32px 圆角、半透明白底的小弹窗。实现时以设计稿结构、尺寸、圆角、颜色和间距为验收基准，并在小窗口下按尺寸约束适配。
- 歌单能力保存的歌曲来源只限当前应用已拥有的歌曲数据，不新增系统媒体库导入、外部文件选择、系统播放列表导入或云端来源。

## 测试决策

- 最高测试缝隙应放在共享应用控制器和歌单仓库契约上，覆盖用户能感知的完整行为：入口点击、弹窗状态、保存结果、即时刷新、详情页队列和空态。
- 数据持久化需要测试歌单创建、名称裁剪、完全字符一致判重、默认名称递增、搜索、排序、更新时间更新、重复添加幂等、不可用歌曲过滤和关系保留。
- 数据库迁移需要测试从当前版本升级到新版本后，新增歌单表可用，既有播放、收藏、搜索历史、本地曲库和偏好数据不丢失。
- 控制器测试需要覆盖：歌单数量为 0 时点击我的页歌单统计不跳转并提示“暂无歌单”；歌单数量大于 0 时进入歌单列表；添加到已有歌单成功后关闭弹窗并显示成功提示；新建歌单成功后关闭两个弹窗并加入当前歌曲。
- 控制器测试需要覆盖：添加到歌单弹窗默认不选中任何歌单，未选择时完成不可用，选择后完成可用。
- 控制器测试需要覆盖：添加成功后我的页数量、歌单列表排序、目标歌单封面、目标歌单数量和详情页歌曲列表即时刷新。
- 控制器测试需要覆盖：重复添加同一首歌到同一歌单时仍显示成功提示，但不更新歌单更新时间、不改变歌单列表排序。
- 播放行为测试需要覆盖：歌单详情页播放全部按当前可用歌曲的加入顺序建队列；点击详情页任意歌曲时使用整个歌单当前可用歌曲列表建队列，并从点击项开始播放。
- 更多面板测试需要覆盖：非歌单详情页显示“添加到歌单”；歌单详情页不显示“添加到歌单”，但保留原有歌曲操作。
- 界面展示测试需要覆盖：歌单列表复用专辑卡片节奏、歌单详情复用专辑详情节奏、空歌单详情页显示置灰播放全部和“暂无可播放歌曲”。
- 移动端页面 chrome 测试需要覆盖：歌单列表页和歌单详情页隐藏底部标签栏、保留全局迷你播放器，内容不被底部 chrome 遮挡。
- 桌面端测试需要覆盖：桌面端我的页歌单统计使用真实数量，数量为 0 时不跳转并提示“暂无歌单”，数量大于 0 时能进入歌单列表，空歌单详情显示置灰“播放全部”和“暂无可播放歌曲”，添加到歌单和新建歌单弹窗行为与手机端一致。
- 弹窗视觉需要在实现后做设计稿对照检查，重点核对宽高约束、圆角、颜色、间距、搜索区域、列表状态、新建入口、按钮状态和最大高度三分之二规则。
- 测试应优先验证外部行为和用户可见状态，不绑定内部私有函数或具体实现细节。

## 非目标范围

- 不做登录、账号体系、云同步、公开歌单、推荐歌单或系统媒体库播放列表承接。
- 不做系统媒体库播放列表导入、外部文件选择导入、从文件夹直接创建歌单或从歌单页导入歌曲。
- 不做歌单列表页的新建歌单入口，也不支持创建空歌单作为独立流程。
- 不做歌单删除、歌单重命名、从歌单移除歌曲或歌单内歌曲排序编辑。
- 不在歌单详情页歌曲更多面板中提供“添加到歌单”。
- 不把不可用歌曲展示在歌单详情页，也不在本次界面中展示失效歌曲提示或失效歌曲管理。
- 不为重复添加显示“已存在”一类打断提示；重复添加按成功状态处理。
- 不为桌面端设计另一套独立弹窗逻辑；桌面端只做尺寸适配。
- 不修改原型目录来替代真实应用实现。

## 补充说明

- 本规格只整理本次已确认的需求和功能逻辑。
- 本地自建歌单是本次需求的核心领域词；歌单详情页、歌单歌曲列表和歌单播放队列应沿用项目领域语言。
- 实现时需要谨慎处理名称规则：首尾空格裁剪，中间空格保留；大小写不同即不同名称；完全字符一致才算重复。
- 实现时需要谨慎处理范围边界：歌单详情页只承担浏览和播放，不承担管理。
- 交付前需要做对抗式审查，重点检查是否误加了歌单列表新建入口、是否在歌单详情页漏出“添加到歌单”、是否把判重做成大小写不敏感、是否让歌单数量为 0 时发生跳转、是否遗漏桌面端入口。
