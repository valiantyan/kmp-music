# UI 与状态规则

本文承接根 `AGENTS.md` 的 UI 细则。只有任务触及移动端导航、全局 chrome、迷你播放器、播放页、桌面播放器、视觉 token 或页面显示模型时才需要读。

## 移动端导航

- 移动端一级导航只有 `首页 / 收藏 / 我的`，对应领域词汇是 `底部 Tab`。
- 搜索、播放页、专辑详情页、歌手详情页、最近播放页、本地音乐、设置、登录、本地自建歌单等属于二级页面。
- 移动端二级页面栈可以继续打开二级页面；返回时回到上一层，并恢复该层自己的底部 chrome 状态。
- 普通二级页不要继承播放页下滑关闭语义。

## 全局 chrome 与播放状态

- 全局迷你播放器由 App 全局 chrome 承载，不属于单个页面内容，不在页面里重复实现。
- 一级页面中迷你播放器与底部 Tab 之间不要留缝；保留迷你播放器的二级页中迷你播放器贴齐底部。
- 沉浸式播放页隐藏底部 Tab 和全局迷你播放器，由播放页自身承载封面、歌曲信息、进度、播放控制和底部辅助动作。
- 无迷你播放器二级页面覆盖在保留迷你播放器的页面上时，底层迷你播放器不执行隐藏或恢复动画。
- 全局当前播放歌曲必须在列表、迷你播放器、播放页和桌面底部播放器中同步，当前歌曲文本保持红色或既有播放中标识。

## 页面职责

- 页面负责布局编排，组件负责复用 UI，控制器负责状态变化；避免在页面级 Composable 里堆业务分支。
- 跨页面复用组件放在 `feature/components` 或更贴近的 feature 子目录。
- 移动端页面显示模型或交互规则改动，应同步检查 `feature/screen`、`feature/app/layout`、`feature/app/navigation`、`feature/app/playerbar` 测试。
- 桌面页面或播放器显示改动，应同步检查 `feature/desktop` 测试。

## 视觉与资源

- 手机 UI 以高保真音乐 App 原型为视觉参考，但生产实现必须是 Compose 原生 UI。
- 设计令牌优先放在 `MusicTheme.kt`、`DesktopMusicTokens.kt` 或对应设计规格；不要为了局部视觉问题在多个页面复制补丁。
- 固定格式 UI 如底部栏、迷你播放器、封面网格、图标按钮、桌面表格、播放器控制区要有稳定尺寸，避免状态变化导致布局跳动。
- 封面、插画和原型资源优先复用 `composeResources/drawable`；新增视觉资产要说明来源和用途。

## 视觉与动态验收

- 动手前在实施方案或对应 issue 中记录本次视觉基准：每个状态对应的设计节点或参考图、目标窗口或设备尺寸及验收证据；不为状态矩阵单独新建文档。
- 状态矩阵只覆盖需求相关状态，按任务从默认、选中或当前项、播放中、暂停、悬停或按下、空数据、长列表滚动中选择；不能只验默认静态页面后推断其他状态正确。
- 用户显式要求 1:1 或截图核对时，参考设计中与本次交互相关的可见状态和动态效果都属于验收项，即使用户没有逐项复述。必须使用本次构建在指定尺寸下的截图与各状态对应的设计节点或参考图比较；截图前确认目标窗口来自本次构建，不能用已安装旧版本或无法识别来源的窗口代替。
- 动画或时间相关行为必须提供本次构建的录屏或连续帧证据，连续帧需要包含不同时间点且能看到实际变化，并覆盖需求定义的开始、持续变化和停止或暂停条件；单元测试只能证明触发规则，不能替代动画实际渲染证据。
- Desktop 首页播放动画、专辑/歌手长列表和自动隐藏滚动条优先使用 `./scripts/desktop-ui-qa.sh <scenario>` 取得固定尺寸连续帧；新增场景必须继续复用真实 Desktop 壳和内存 fake 数据。
- 显式验收证据缺失时任务状态是未完成，不能以“有条件通过”或“剩余视觉风险”交付、提交。只有用户未要求、且不影响验收结论的补充截图或人工观察，才允许作为剩余风险说明。
- 截图、录屏和原始设计附件只作为验收证据，不默认提交到仓库；最终说明要列出实际核对的构建、尺寸和状态。
